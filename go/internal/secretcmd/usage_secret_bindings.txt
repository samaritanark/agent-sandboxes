
BINDINGS (v3):
  In v3 the agent never sees a secret's value unless you allow it. A secret
  a session names is brokered: the agent gets a placeholder, and the session's
  gateway puts the value into requests to the hosts the secret is bound to.
  A secret with no binding is withheld.

  sandbox secret set <NAME> [...] [--bind HOST[,HOST]...] [--inject KIND]
  sandbox secret set <NAME> [...] --allow-readable
  sandbox secret bind <NAME> (--bind HOST [--inject KIND] | --allow-readable | --withhold)

  --bind HOST       Exact host the broker may send the secret to (repeatable).
  --inject KIND     How: bearer (default), basic, header:NAME, or query:NAME.
  --allow-readable  The agent may read the value itself (as $NAME, from a
                    file under /run/sandbox/secrets). Not brokered.
  --withhold        Remove the binding.

  'set' without binding options keeps the secret's binding. The binding is
  sealed with the value when a session's secrets go to the sandbox VM, so the
  VM cannot send the value anywhere else.

  # Brokered to the GitHub API as a bearer token
  sandbox secret bind GH_TOKEN --bind api.github.com
