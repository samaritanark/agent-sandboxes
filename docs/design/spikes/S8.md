## Rough port estimate

Not ported (replaced or deleted in v3, per §5.4.1): `cluster`, `network`,
`lima`, `dns`, `policy`, most of `platform`, and the Kubernetes parts of
`manifest`, `dependency`, `secrets`, `credentials`, and `resources`.

Candidate for port: about 7,300 lines of `lib/` (`filesystem`, `vetting`,
`checks`, `link`, `audit`, `onboard`, `config`, `agents`, `catalogue`,
`secrets`, `profile`, `credentials`, `tier`, `certs` in part) plus roughly half
of `bin/sandbox`: **on the order of 10,000 lines of bash, plus the tests that
cover them.** This is a sum of whole files and the doc's 50% estimate, not a
per-function measurement.

## Test classification (regex heuristic, 2026-11-18; first cut, not an audit)

Each `tests/test-*.sh` was classified by counting lines that source `lib/`
files, invoke the CLI, or use Kubernetes, Cilium, gVisor, Lima, or firewalld
tooling.

| Class | Files | Lines | Meaning for the port |
|---|---|---|---|
| Bash-function unit tests (source `lib/*.sh` and call functions) | 21 | 9,046 | Port with the module they cover; run against both implementations until the bash is deleted |
| Kubernetes, runtime, or platform tests | 28 | 6,262 | Replaced by the v3 enforcement suite, not ported (§7, §9), after pulling out any pure-policy assertions |
| Other (`test-buildkit-gc.sh`) | 1 | 57 | Buildkit GC; image pipeline |

Largest portable files: `test-secret-gate.sh` 2,071 lines, `test-vetting.sh`
1,614, `test-audit.sh` 804, `test-onboard.sh` 607, `test-link.sh` 516,
`test-allow.sh` 407, `test-profile.sh` 373. Together with `helpers.sh` (39
lines) the totals match the 15,404 lines counted earlier.

Observations:
- **No file is purely CLI-driven.** Every portable test sources library
  functions directly, so none can be re-run unchanged against a Go binary; they
  have to be ported with the code. The doc's "about 62%" carries-over estimate
  is 59% by this count.
- **The "replaced" share is higher than the doc's 25%** (41% here). The
  heuristic counts a file as replaced when it uses Kubernetes tooling more than
  five times, which includes tests that mix policy assertions with `kubectl`
  setup (for example the three `test-credentials-*` files and `test-filesystem`,
  `test-blocked-cidrs`, and `test-policy-deps`). Some of that is portable policy
  logic, so a per-file read is needed before the replaced bucket is trusted.
- The two largest portable files (`test-secret-gate.sh`, `test-vetting.sh`) are
  the S8 pilot's own targets and together are about 3,700 lines of tests.
