# S5 — Gateway

**Status:** started. A prototype of the gateway contract in §5.8.4 and the
credential behaviour in §5.9.3 ran on Envoy, with a Lua filter standing in for
the broker. The broker (`ext_proc`), upstream TLS and mTLS re-origination,
upgrades and long-lived streams, ECH, corporate-proxy chaining, the Go
controller, and the unprivileged-user and seccomp posture were not tested, so
the exit criteria are not met.

## Environment

- Envoy 1.40.2 (`envoy-1.40.2-linux-aarch_64`, a 100 MB BoringSSL build), run
  as root inside the gateway namespace `gwA` of the S1 topology (appliance VM:
  Ubuntu 24.04 arm64, nested on an Apple M6, Lima 2.3.0). The Envoy download was
  not checked against a vendor digest (the release lists none).
- Clients ran in the agent-side namespace `agA` with `curl` (HTTP/1.1 and
  HTTP/2) and `nc`, not in a Kata microVM; the microVM-to-gateway path was
  covered in S1.
- Test CA and leaf certificates were generated with `openssl` (P-256). The
  upstream was a small Python server in the VM root namespace
  (`10.201.1.1:9000`) that echoes request headers, can redirect with the token
  in `Location`, and reports server-side whether it received the real
  credential (`X-Authorized`).
- Config: one listener on the gateway link address with `tls_inspector` and
  three kinds of match: **intercept** (TLS terminated; HTTP connection manager;
  route rules; Lua filter), **passthrough** (`sni_dynamic_forward_proxy` plus
  `tcp_proxy`), and **no match** (connection closed).

## Results

| Contract item | Result |
|---|---|
| Allowlisted SNI passes through to the real server (§5.8.4 item 3) | **Pass.** `example.com` returned HTTP 200 and the client verified the real public certificate (the gateway did not terminate TLS) |
| Missing SNI, or an SNI not on the allowlist, is denied | **Pass.** `evil.com` and a connection by IP were both closed during the handshake |
| Wildcards are single-label by default (§5.8.7) | **Pass.** `*.example.org` matched `x.example.org` and did not match `a.b.example.org` or `example.org` |
| `CONNECT` from the guest and plain HTTP | **Pass.** A plaintext `CONNECT example.com:443` sent to the TLS port got no response and a closed connection; port 80 is closed |
| Authority must match SNI on intercepted connections (§5.8.4 item 9) | **Pass, with a filter.** Envoy does not compare them itself; a Lua check of `requestedServerName()` against `:authority` returned HTTP 421 on HTTP/1.1 and on HTTP/2 |
| L7 baseline on an intercepted host (§5.8.5): deny `POST` to `*/git-receive-pack`, deny `service=git-receive-pack` advertisements, deny `PUT` and `DELETE`, deny `TRACE` and `TRACK`; allow `GET` and a `service=git-upload-pack` fetch | **Pass.** Route-level rules returned 403 for each deny case and 200 for the allowed cases, as protocol rules (no per-host list) |
| Credential injection: a placeholder is replaced by the real value (§5.9.3) | **Pass (Lua).** The upstream reported `X-Authorized: yes`; the same worked over HTTP/2 |
| A guest-supplied non-placeholder `Authorization` is not forwarded | **Pass (Lua).** The upstream saw no `Authorization` header |
| A placeholder sent to an unbound intercepted host is blocked and recorded | **Pass (Lua).** HTTP 403, and the proxy log recorded `credential_misuse` |
| Response scrubbing (F3): the real value is replaced in response headers, a redirect `Location`, and a JSON body | **Pass (Lua).** The guest saw only the placeholder in `X-Echo-Auth`, in `Location`, and in the body |
| Blocked CIDRs after resolution, with no resolve-then-dial gap (§5.8.4 item 2, P-07) | **Pass, by nftables, not Envoy.** The name `169.254.169.254.nip.io` resolves to the metadata address; a rule in the gateway namespace's `output` chain rejected the connection to the address actually dialled (counter: 2 packets, logged). | Audit log redaction (§5.12): query strings stripped, no credential or placeholder values | **Pass.** Using `%REQ_WITHOUT_QUERY(:PATH)%`, no log line held a query string, the real token, or a placeholder; the formatter has to be declared as an extension (`envoy.formatter.req_without_query`) or the config is rejected |

## Findings that change the design

1. **Blocked CIDRs belong in nftables on the gateway namespace's output
   chain**, not in the proxy. It checks the address actually dialled, so the
   check-then-connect gap in §5.8.4 item 2 cannot occur. The gateway's DNS
   queries to the upstream resolver need an explicit exemption: my first rule
   set included the resolver's `/24` and would have blocked name resolution.
2. **The root namespace needs its own input filtering on the uplink
   interfaces.** Before this, nothing stopped a gateway-namespace process from
   reaching listeners in the VM root namespace through the uplink address. With
   an `iifname "up…" drop` rule (allowing only the test port) the gateway
   namespace could no longer reach the VM's `sshd` on port 22. I only tested
   after adding the rule, so the "before" state is by construction, not
   measured. §5.8.2 describes rules for the gateway namespace but not for the
   root side.
3. **A new namespace has no working resolver** (S1), confirmed again: the
   gateway namespace needs an explicit upstream resolver address, set here
   through `/etc/netns/<ns>/resolv.conf` (the VM's gvisor-tap-vsock gateway,
   `192.168.5.2`).
4. **Envoy's own wildcard matching is already single-label**, which matches the
   design's default. The explicit multi-label `**.` form (OQ-10) is not
   something Envoy provides; it would need generated `server_names` entries or a
   controller-side match.
5. **Authority-versus-SNI checking and credential logic need filter code.** A
   Lua filter was enough for the prototype; the design's `ext_proc` broker
   (§5.8.4 data plane note) will take its place and was not tested. Lua buffers
   whole bodies for scrubbing, so streamed responses (SSE) are untested and
   probably need the sliding-window approach already described in §5.9.3.
6. **Per-session cost is small:** about 65 MiB and 0.1 s per gateway process.
   With one namespace per session, the "process per session or per namespace"
   question in §8 resolves to the same thing; six sessions would be about
   400 MiB of gateway memory, which should go into P-24.
7. **Passthrough is effectively free here**, so intercepting only the
   destinations that need L7 or credentials (§5.8.4 item 4) is a performance
   choice that costs nothing to keep.

## Not done

- The broker: `ext_proc` credential injection with an encrypted store,
  placeholder format and rate limits, a real per-session CA and leaf issuance
  (§5.10), and the token-endpoint adapters.
- Upstream TLS: re-encryption with certificate validation against system roots
  and the corporate CA bundle, mTLS client certificates with `tls-server-name`,
  chaining through a corporate proxy.
- WebSocket and SPDY upgrades (for `kubectl exec` and `port-forward`),
  server-sent events and other long-lived streams, and large intercepted
  bodies.
- ECH handling, request smuggling, malformed `ClientHello`s, oversized DNS
  (N-14 is only partly covered above), and HTTP/2 connection reuse across
  authorities.
- IPv6, non-443 declared ports, dependency links (gateway to a dependency
  microVM), and hot allowlist extension without dropping connections.
- Running Envoy as an unprivileged user under seccomp (it ran as root and bound
  port 443 directly), and the Go controller that would compile session policy
  into configuration.
- More than one session, and a Linux host.

## Harness notes

Two harness mistakes cost time and are recorded because they will recur:
processes started with `nohup … &` in one SSH session did not survive the
session ending (`setsid -f` did), and truncating a log file that Envoy still
held open left the file starting with NUL bytes, so `wc -l` undercounted its
lines.
